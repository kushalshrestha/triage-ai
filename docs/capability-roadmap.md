# Capability roadmap

Starting with Phase 9, phases increment as one continuous sequence
across all capabilities (knowledge ingestion, agent orchestration,
guardrails, LLMOps, etc.) rather than restarting the count per
capability. This file is the single source of truth for "what phase
are we on" — update the Status column as part of finishing a phase,
not as an afterthought.

| 22 | Evaluation Framework | LLM-as-judge for draft quality — found this named-since-early ("LLM-as-judge quality ≥ 4/5" in testing-strategy.md) capability was never built; new 1-5 quality judge + 12-example golden set measured 1.00 consistency / 0.917 reliable_accuracy on Ollama, contradicting the expectation (from the groundedness judge's 0.636 ceiling) that a graded task would be harder — no Claude comparison needed (see ADR-0025) | Done |
| 23 | AI Safety | Red-team/adversarial set — found the 4-example set was tautological (built from the guardrail's own keyword list); grew to a 14-example categorized golden set (direct 100%, evasion 0%, false-positive 100% after a one-line fix, semantic-hijack 0% — all measured, not assumed); new defense-in-depth eval proved semantic-hijack tickets that bypass the input guardrail still can't produce an unauthorized `auto_respond`, and pinpointed which mechanism actually catches it (retrieval-threshold routing for 3/4 scenarios, citation-scoped groundedness for the 4th, deliberately engineered for high similarity) (see ADR-0026) | Done |
| 24 | Input Guardrails | Fixed a real PII leak — `redact_pii()` was applied before retrieval/classification but `generate_draft()` built its Claude prompt from the raw `Ticket` object, sending unredacted PII to Claude's API despite a `PII_REDACTION` guardrail check recording as passed; fixed by removing `generate_draft()`'s access to raw ticket fields entirely (it now only takes already-redacted strings), closing the gap structurally rather than patching one call site; new regression tests assert redacted text actually reaches the mocked Claude call, closing the test gap that let this go uncaught (see ADR-0027) | Done |
| 25 | Output Guardrails | Found all 3 model-call sites (Ollama classification, Ollama groundedness judge, Claude drafting) handled bad output but not the call itself failing — an unreachable Ollama or erroring Claude API raised uncaught, crashing the whole triage request with a 500 instead of failing safe; fixed by translating each call failure into the same shape as an already-handled bad-output case (Ollama-down → Claude fallback; judge-down → not-grounded; Claude-down → DraftSchemaError/escalate) at the call site, requiring zero `orchestrator.py` changes since its existing bad-output handling was already the correct fix (see ADR-0028) | Done |
| 26 | Evaluation Framework | Groundedness judge model comparison (first of 4 deferred enhancements) — measured Claude against the same golden set ADR-0020 used: Claude scored a perfect 1.00 consistency/reliable_accuracy vs. Ollama's 0.636, and critically, 100% of Ollama's errors were false positives (said "grounded" when it wasn't) — the dangerous direction for a guardrail gating `auto_respond`. Switched `orchestrator.py`'s groundedness check to `provider="claude"` (scoped to this one call site only — classification, draft quality, and contextual retrieval all keep their Ollama defaults) since this ticket already paid for a Claude drafting call to reach this point (see ADR-0029) | Done |
